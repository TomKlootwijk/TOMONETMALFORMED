## Page 2: What this document defines

<b>Perpetuum Mobile is a family of systems that continually observe, transform and reconstitute state.</b> The common object is a typed, causal loop. Its embodiments range from reproducible digital spaces to dissipative material computers and resource-limited physical installations.

The application versions are different engineering proposals. Each has a task, an embodiment, domain equations, a mapping from the supplied operators, a measurable output, an experiment and a future extension. A new version is justified by a different mechanism or contract.

```text
formal source -> typed contract -> application model
             -> implementation -> observed evidence
```

Formalizing the formalization

The transformation from a source statement to an executable or measurable claim is itself recorded: source locator, interpretation, domain, equation, assumptions, proof obligation and evidence. Ambiguous source meanings remain separate until an explicit adapter relates them.

Meaning of continuing operation

In a digital system, continuation means successive valid transitions within declared memory and execution budgets. In a physical system, it means operation sustained by accounted energy and material flows. Ideal conservative models and physically powered devices have different continuation conditions; page 14 states those conditions.

<b>Evidence status of this edition:</b> a formal design synthesis with newly executed software and calculation checks. The application integrations are proposed architectures. The cited hardware and material studies establish bounded component evidence, and do not establish that these seven integrations have been built.

## Page 5: The formalization is an object

[D] Let a source statement be a record s with document hash, page, exact subject and context. A formalization step N produces a candidate contract K and a disposition record e. N(s, interpretation) = (K, e)

An unavailable optional observation may coexist with a committed transition. A rejected transition cannot publish its candidate as authoritative.

A contract must answer six questions

| Question | Required content |
| What exists? | All retained state, identity, units and external resources |
| What changes? | Transition, event order, update interval and physical evolution |
| What may fail? | Domain exclusions, unknown inputs, resource exhaustion and fault policy |
| What is preserved? | Scoped invariants and the assumptions needed for each |
| What can be observed? | Readout, calibration, uncertainty and comparison rule |
| What supports it? | Source locator, derivation, executed check or measured evidence |

[D] Registry closure and type checking establish structural consistency. They do not decide all semantic propositions or prove arbitrary programs terminate. This meta-layer records unresolved obligations instead of assigning them a default PASS.

## Page 11: SEED / Exact digital construction

[D] This new reproducibility contract supplies digital initialization and experimental stimuli. H is SHA-256; || is byte concatenation; U16/U64 are unsigned big-endian fields. Every displayed \0 is a single NUL byte. Lengths count bytes; overflow is rejected.

The core seed S is exactly 32 bytes: an integer in [0,2^256), persisted as 64 lowercase hex digits. A decimal adapter accepts canonical ASCII unsigned decimal only. Optional text input uses strict UTF-8, with no normalization, trimming or case folding, and hashes a length-framed string:

```text
S_text = H("PPM/TEXT/v1\0" || U64(len(t)) || t)
m = H("PPM/MANIFEST/v1\0" || U64(len(C)) || C)
K = H("PPM/SEED/v1\0" || S || m)
```

C is a constrained canonical JSON manifest with exactly nine root fields: <b>schema, family, sub_v, numeric_mode, seed_hex, sources, assets, algorithms, parameters</b>. schema is ppm-seed-v1; seed_hex encodes S. Source/asset lists contain unique, ID-sorted {id,sha256} records. Profile IDs and sampling domains are lower ASCII slash-separated identifiers.

Canonical encoding uses UTF-8 without BOM, recursively sorted ASCII keys, no token whitespace and preserved array order. Keys match [a-z][a-z0-9_]*. Values may be null, booleans, Unicode scalar strings, lists or objects. Reject duplicate keys, invalid Unicode, JSON numeric tokens and nonfinite values. Numeric quantities use schema-typed strings. Strings follow RFC 8785 escaping, preserving their Unicode sequence; this is a deliberately restricted subset [R7, R8].

The application schema fixes units, constant representations, initialization, algorithm versions and resource limits. Source/asset hashes bind exact bytes; no field may contain its own manifest/output digest. Host paths and incidental timestamps belong in a receipt unless they affect the mathematics.

The embedded seed_reference_v1.py fixes all byte rules, rejects and fixture values. Its generic validator checks seed/manifest structure; a complete application must also resolve referenced contents and validate its own parameters. The custom stream is a new definition, not a standardized random-bit generator or a source of physical randomness.


## Page 12: SEED / Streams, evidence and replay

```text
B(d,c) = H("PPM/BLOCK/v1\0" || K || U16(len(d))
           || ASCII(d) || U64(c))
x = unsigned_big_endian(B(d,c)[0:8])
L = 2^64 - (2^64 mod n)
advance c after every draw; accept x < L;
output x mod n; otherwise retry
```

[D] Domain d has 1..65535 ASCII bytes; each slash-separated component matches [a-z0-9_.-]+. Counter c is 0..2^64-1. The u64 sampler consumes one 32-byte block, uses its first eight bytes and discards the rest. For n in 1..2^64, record every rejected draw and advance only that domain. Use arithmetic wide enough to represent 2^64. A next counter equal to 2^64 is terminal and is never hashed. A unit-grid API in a distinct domain returns (x &gt;&gt; 11)*2^-53 in [0,1).

Use stable logical identities and sampling-site names, such as geometry/instance/0/position. Worker IDs and arrival order cannot define random streams. The range mapping removes modulo bias conditional on uniform input words; this does not prove a finite public seed set has perfect statistical distribution.

```text
T0 = H("PPM/TRANSCRIPT/v1\0" || m
       || U64(len(X0)) || X0)
T_(i+1) = H("PPM/EVENT/v1\0" || T_i || U64(i)
          || U64(len(E_i)) || E_i)
```

X0 is exact family-defined initial-state bytes; E_i is a constrained-canonical event object. Record input/measurement content, logical order, draw counters, outcomes and state checkpoints. A receipt binds terminal count and chain head. Replay recomputes transitions and reports the first divergence; an unsigned hash alone establishes neither execution truth nor authorship.

<b>Replay modes:</b> exact integer/fixed-point state; explicitly pinned binary64 environment; numerical tolerance with units and exact discrete statuses; or measurement compatibility. Each is a different claim [R22]. Transcendental implementations, operation order and physical sensor novelty require their own records.

Physical timestamps, calibration, actual commands and measurements are never regenerated retroactively from a seed. WB uses ties-away rounding; a new fixed-point profile must declare its own rounding. The SEED reference does not implement WB, and adapters must preserve the selected source arithmetic.

[P] Fix the complete initial state, semantic descriptor, seed bytes, input transcript, numeric rules and event order. ```

[P] Induction proves this statement for the digital state. A physical invariant additionally needs a property of Flow and the actuator/readout interface. Checking only T leaves the intervening continuous trajectory unconstrained.


[D/P] R relates a model state x and an implementation or physical state z. The relation may require a quantization cell, tolerance, operating domain and finite horizon. An exact digital adapter uses equality of decoded observables. An approximate physical adapter needs error propagation and measured parameter uncertainty.

P4 / Continuous event validity

[D] A geometric guard must have a certified root/crossing within the search interval, or an explicit no-event/unknown result. Define initial contact, tangency, simultaneous roots and search exhaustion. Samples that miss a boundary cannot establish continuous clearance.

## Page 14: The perpetuation condition

```text
E(t1)-E(t0) = integral[P_in - P_useful - P_loss] dt
Repeated cycle: integral(P_in) dt
             = integral(P_useful + P_loss) dt
```

[L/P] For a repeated cycle whose complete stored-energy state returns to its starting value, net supplied energy equals delivered output plus losses. Any harvested light, heat gradient, fuel, pressure, gravity change or replenished material belongs in the boundary account. The sign convention follows energy conservation [R1].

A finite reserve gives a finite bound

```text
P_in = 0, P_useful + P_loss >= p0 > 0, E >= E_min
        => t_run <= (E_start - E_min) / p0
```

[P] Integrating the energy inequality proves the bound. If losses are zero in an ideal model, persistent motion may exist without useful net extraction; extracting energy changes the reserve. A topology label, seed, matrix determinant or reset cannot cancel an energy term.

Digital recurrence and physical endurance

[P] An autonomous deterministic finite-state core eventually revisits a state. Periodic external input may be included by augmenting the core with its phase. An unbounded counter or growing trace is additional state; a finite implementation must stop, checkpoint, or declare wrap behavior. Eventual digital recurrence does not establish an infinite hardware lifetime.

[D] Every physical application therefore states a mission horizon H, input-resource schedule, storage bounds, degradation model and service condition. Its continuation claim is conditional on those quantities remaining inside the admitted envelope.

S1 PDF pp. 13-19 and S4 p. 16 already distinguish physical energy from symbolic operations. PM uses the title for sustained recurrence and explicitly retains the energy balance. No zero-input, positive-output perpetual device is established here.

## Page 18: V02 / Material memory and computation

<b>Task:</b> classify or predict a time-dependent signal by letting actual material dynamics retain and mix recent input history. The useful output is a temporal feature vector read from the device.

[D/M] The reference architecture is a small array of electrically driven, thermally coupled resistive-memory cells. A lower-complexity physical experiment can use heater/thermochromic cells with a separate observation law. Heat transport follows its balance [R2]; colour and material phase need separate calibrated histories [R3]. These are distinct device choices. Dynamic memristor experiments support material-based temporal processing [R9]; thermal-neuristor research supports electrothermal cell dynamics and small-group interactions, while its larger reservoir networks are numerical studies [R10].

```text
C_e,i * dv_i/dt = (u_i-v_i)/R_L,i - v_i/R_i(T_i,h_i)
C_th,i * dT_i/dt = v_i^2/R_i(T_i,h_i)
                  - G_iA*(T_i-Ta) - sum_j G_ij*(T_i-T_j)
h_i(t+) = H_i(h_i(t-), T_i; calibrated thresholds)
```

v and u are voltages [V], C_e capacitance [F], C_th heat capacity [J/K], R resistance [ohm], and G thermal conductance [W/K]. Require positive capacitances/resistances, G_iA &gt;= 0 and G_ij = G_ji &gt;= 0. The hysteresis state h requires a material-specific law. An ionic memristor cannot inherit this thermal law merely because both devices have memory.

The supplied architecture has concrete work to do

[D] UGTS binds each physical cell, calibration and permitted coupling to a typed graph. atomOS masks select addressed stimuli and record which requested batches were admitted. WANTWOMBAN supplies the power-to-heat-to-optical-feedback path when thermochromic observation is used. A physical decoder maps logical sites to electrodes; XOR selects bits while currents and heat combine by real-valued laws.

Cell calibration includes initial material state, drift, threshold history, read disturbance and actual voltage/current. An ASA rejection cannot remove heat or charge already delivered.
